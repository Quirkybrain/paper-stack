# ADR-006 版本/代次正确性与更新模式（Version/Generation Correctness and Update Modes）

- **Producer**: agent:solution-architect
- **Status**: VALID
- **Decision Status**: Accepted
- **Revision**: 1
- **Last Verified**: 2026-10-07
- **Date**: 2026-10-07
- **Deciders**: solution-architect
- **Affected Artifacts**: `contracts.md` §6–§7、`architecture.md` §5.2/§7、`data-model.md` §3.3

## Context

R22 要求记录磁盘观测版本与展示版本，任务携带文档、版本、代次，只接受仍匹配当前目标的结果；通知合并、稳定读取和窗口重新聚焦复核配合；图片变化也使对应资源失效。AT22 要求**人为制造 v1 晚于 v2 完成**时页面不得回退，并覆盖替换保存、快速连续保存、只改图片与关闭标签期间完成任务。R21/IXD §10.2 定义“保持/跟随”两种模式与提交条件（前台、无选区、无覆盖操作），后台标签暂存、激活后再检查；IXD §10.3 要求资源单独变化只重挂相关内容。NF07 要求取消有即时反馈且旧结果不能再提交。

## Options

- **A：Future 取消 + 完成时间排序**。取消是尽力而为；迟到的必然存在；时间戳无法表达“当前目标”，易回退；否决。
- **B：每文档串行任务队列**。避免乱序但阻塞新版本处理（v2 等 v1），且无法取消已排队结果；不满足 AT22 的“不等待旧任务”。
- **C：内容哈希作版本 + 单调 generation + 提交规则**。结果自描述，代次表达“当前目标”；旧结果自然被丢弃；可对焦点复核、关闭、撤销统一失效。
- **D：以文件 mtime 作版本**。mtime 可相同/回拨，替换保存场景不可靠；否决（哈希为版本，mtime 仅作复核提示）。

## Decision

采用 C，并落到规范文本：

1. 版本 = 原始字节 SHA-256（`VersionInfo.contentHash`）；`generation` 为每标签单调计数器，目标改变即递增（打开/重定位/接受新候选/关闭/撤销）。
2. 提交规则以 `contracts.md` §6 为唯一权威：`(docId, generation, version)` 全匹配才允许提交；旧结果必须丢弃且禁止回退（AT22/IT04）。
3. 监测/稳定/复核以 `contracts.md` §7 为唯一权威：事件仅提示、防抖合并（W1 初始 300ms）、稳定读取（S1 初始 150ms、最多 5 次）、替换保存经父目录侦察、窗口聚焦复核、资源 `kind=resource` 失效与 `?v=` 缓存破除。
4. 更新模式：全局默认“保持”；当前文档覆盖仅会话内；跟随模式只在活动标签、无选区、无检查层时提交；后台标签暂存并在激活时复查；主动更新需显式“更新并清除选区”（R21；IXD §10.2）。
5. 资源失效只重挂相关块，不重建整篇（IXD §10.3）。
6. 参数（W1/S1/N、去抖）为可校准初值，测试固定后作为回归依据（NF11）。

## Consequences

- 正面：乱序、取消、关闭、撤销共用同一失效机制；提交点单点可测；不会出现“过期内容看似已同步”。
- 代价：所有异步链路必须携带令牌（解析、资源、位置、诊断），实现与用例模板需统一；错误/诊断也受令牌约束。
- 行为取舍：不稳定读取保持旧展示并有重试入口（R22），不提示虚假成功；跟随模式暂停时给出“已暂停自动更新”的明确状态。
- 测试必须按 AT22 强制乱序（人为延迟 v1）与替换保存；这是验收关键用例。

## Constraints

- 不得以“旧任务自行退出”作为正确性前提（R22 明示不依赖）。
- 不得把语义错误当作“未保存”：已稳定但语法错误应提交新版本并给局部诊断（IXD §10.3）。
- 图片变化必须使对应资源失效（R22），由 §7 资源监测覆盖。
