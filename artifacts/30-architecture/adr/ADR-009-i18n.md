# ADR-009 国际化资源包（i18n Resource Bundles）

- **Producer**: agent:solution-architect
- **Status**: VALID
- **Decision Status**: Accepted
- **Revision**: 1
- **Last Verified**: 2026-10-07
- **Date**: 2026-10-07
- **Deciders**: solution-architect
- **Affected Artifacts**: `architecture.md` §8、`contracts.md` §5（messageKey）

## Context

PC-06：首版界面简体中文；界面文案/字符串独立保存、不得硬编码自然语言字符串，为后续英语界面留出空间（计划书 §2.1；`config/project.md`；框架 `docs/internationalization.md`）。v0.1.0 无运行时切换语言的产品要求，但要求单代码库、按 locale 独立文件、键值查找、缺失键回退。Rust 侧错误若直接返回中文文本会把展示逻辑固化在后端，且违反“文案独立保存”。

## Options

- **A：引入 `react-i18next` 等成熟库**。生态成熟，但增加依赖与运行时（v0.1.0 单一语言、无切换需求）；与计划书“首版不额外引入大型框架”的取向不完全一致。
- **B：自研轻量模块（`t(key, params?)` + `locales/{locale}.json`）**。零依赖、可单测；调用签名与主流库兼容，后续可按需替换实现而不改调用点。
- **C：字符串集中常量文件 + 直接引用**。不满足“键值查找/回退/按 locale 文件”的规范；易退化为硬编码；否决。
- **D：Rust 返回中文文案**。违反文案独立保存，且前端无法统一管理；否决。

## Decision

采用 B，规范如下：

1. 资源文件：`src/locales/zh-CN.json`（基准语言，扁平点分命名空间，如 `common.actions.cancel`、`error.io.notFound`）；未来语言新增 `src/locales/{locale}.json` 并注册，禁止分叉代码或按语言复制业务逻辑。
2. 查找函数：`src/app/i18n/` 提供 `t(key, params?)`，支持 `{name}` 参数插值（不做字符串拼接）；语言包按需加载（v0.1.0 仅 zh-CN）。
3. 回退链：当前 locale 缺失 → 基准 `zh-CN` → 原样返回 key 并记录开发期警告；不得空白或抛未捕获异常。
4. Rust 不返回用户可见文本：错误统一携带 `messageKey`（contracts.md §5）；前端将 `messageKey` 解析为文案，异常时附错误编号。
5. 键完整性：`zh-CN.json` 与代码中出现的所有 `t()` key 由测试/审查核对；新增 key 必须同时加入资源文件（框架 i18n 规范的质量审查项）。
6. 界面文案膨胀预留 20%–40%（未来长语言），由 UI 规格/UX 任务执行，本架构仅要求容器弹性。

## Consequences

- 正面：零依赖；与未来 react-i18next 兼容（键命名、插值、回退语义一致），替换成本低；文本审核集中于单一文件。
- 代价：需要自建键完整性与回退测试；参数插值功能有限（不做复数/性别等，v0.1.0 不需要）。
- 风险：开发期若绕过 `t()` 直接写中文字符串会破坏规范；由质量审查静态检查硬编码文本（i18n 政策要求）。

## Constraints

- 单一代码库；不得出现“中文版代码/英文版代码”或多套逻辑（框架 i18n 铁律）。
- 界面文案不得硬编码于组件、服务或 Rust；`messageKey` 是错误契约的一部分（contracts.md §5）。
- 语言包随包离线可用（NF02）。

## Affected Artifacts

- `architecture.md` §8（i18n 策略）、§2.2（`src/locales/`）。
- `contracts.md` §5（`messageKey` 字段与命名约定）。
- 下游：`src/app/i18n`、全部界面组件、质量审查清单（硬编码检索）。
