## 1. 效力、范围与统一口径

### 1.1 本基线的地位与效力

- **产品行为权威**：SRS 定义产品可观察行为与验收（R01–R30、NF01–NF12、AT01–AT30、IT01–IT08）；IXD 定义入口、反馈、状态、焦点与退出（IX01–IX15、UI00–UI08）；计划书固定名称、归属、协议、平台、技术框架与版本方向（SRS §1.1；IXD §1.2；Intake §3）。本基线不改写上述文档。
- **效力**：SRS §1.3——“v0.1.0 是当前唯一必须完成的产品版本”“所有‘必须’‘通过’都是将来的行为要求”；R01–R30 全部为 **v0.1.0 / Must**（SRS §1.1；SRS §4.1–§4.10 节首）。
- **冲突规则（必须遵守）**：SRS §1.3——“出现同一产品规则的冲突时，应统一两份文档后再作为验收依据，**不由实现自行挑选较宽松条件**。”本基线未发现行为级冲突（Intake §4.4）；IXD 汇总表与章节的标注粒度差异按 §7.2 统一；下游如发现真实冲突，必须记录具体条款并回到 SRS／IXD 统一后重新基线化。
- **编号纪律**：R01–R30、NF01–NF12、AT01–AT30、IT01–IT08、F01–F07、IX01–IX15、UI00–UI08 均为产品追踪标识（SRS §1.3；IXD §1.3）。本基线**不新增、不删除、不改号**；DR-01–DR-08 仅为交付要求登记，不是产品需求编号（来源见 §6）。

### 1.2 范围与非目标

- **v0.1.0 交付目标**：可安装并用于日常阅读的 Markdown 与数学公式阅读器（计划书 §5.1）。技术路线与工程元数据依据计划书与 `config`（Tauri 2、React/TypeScript、Rust、Vite、SQLite；`config` 行 31–43）。
- **首版包含**：文件打开、目录阅读、文档会话（多标签）、Markdown/GFM、公式、代码块、Mermaid、内容查看、大纲与导航、页内搜索、阅读状态、文件更新、显示设置、权限与隐私、Linux 交付（计划书 §5.2；SRS §4）。
- **非目标（首版明确不包含）**：编辑、自动格式化、账户、云同步、多人协作、Git 管理、代码执行、终端、调试、插件市场、打印导出、OCR、完整 PDF 与 TeX 编译（SRS §2.4；计划书 §1.3、§5.5）。
- **范围外版本**：F01–F07（v1.0／v1.x）明确排除，见 §7.4（SRS §9.1；计划书 §6.1）。

### 1.3 术语（SRS §1.2）

- **文档身份**：应用确认的同一文件，不只由文件名决定。
- **内容版本／展示版本／待更新版本**：内容版本是一次读取的内容快照；展示版本是用户眼前正在阅读的快照；待更新版本已观测到但尚未替换展示。
- **阅读锚点**：语义块及其相对位置，不只是滚动像素。
- **当前文档会话／应用会话／授权根**：当前文档会话是某标签当前正在查看某文档的生命周期；应用会话从启动到退出；授权根是用户明确允许访问的目录范围。

### 1.4 横切约束（登记，不新增需求编号）

- **界面语言与文案**：首版简体中文；界面文案/字符串独立保存、不得硬编码自然语言字符串，为后续英语界面留出空间（计划书 §2.1；`config` 行 51；框架 i18n 默认规范）。
- **归属与许可**：产品名称“纸栈 PaperStack”；所属者 Quirkybrain；原创代码 GPL-3.0-only（不默认追加“或任何后续版本”）（SRS §3.4；计划书 §1.4）。
- **引用纪律**：`[S0x]` 为各文档局部命名空间（Intake §4.3 O3）；本文所有引用写明来源文档；下游禁用裸 `[S0x]`（A7，已按此执行）。
- **语义规则承接**：SRS §5.1–§5.3 的公式/代码/搜索样例、链接与授权优先级、搜索与源映射规则已并入对应 R 条目（R05、R10、R11、R15、R17、R19、R25、R26 等）；原文仍为权威。

### 2.1 文件入口与输入（SRS §4.1）

#### R01 统一文件打开

- **优先级**: Must（v0.1.0；SRS §4.1 节首）

- **异常／取消**: 取消选择**不得**改变现有界面；单个失败**不得**清空其他文档；非文档拖放、无效路径和未授权路径**不得**被解释为命令。（SRS §4.1 R01）
- **验收**: AT01（SRS §4.1“验收 AT01”；SRS §8.1）
- **交互／区域**: IX01；UI00、UI01、UI07（SRS §4.1；SRS §8.1）

#### R02 普通目录阅读

- **优先级**: Must（v0.1.0；SRS §4.1 节首）

- **异常／取消**: 隐藏项、无权限目录和符号链接**必须**有可解释状态；解析后越界的目标重新授权；打开空目录不显示假文档；不递归导入全盘。（SRS §4.1 R02）
- **验收**: AT02（SRS §4.1“验收 AT02”；SRS §8.1）

## 6. 交付要求 DR-01–DR-08

- **来源限定**：本节仅由 `config/project.md` 与用户指令 `state/handoffs/wp-00-start.request.md` 推导；每条给出源行号。DR 编号是交付要求登记，**不是产品需求编号**（不改变 R/NF/AT 体系）。

**DR-01 交付物必须包含实际应用代码。** 交付必须包含实际运行的应用代码；分析文档或静态展示页面不能替代产品实现。来源：`wp-00` 行 25；`config` 行 17（Target Stage=release）。

**DR-02 尽早运行真实主阅读页并逐项核对。** 必须尽早运行真实主阅读页，并按《交互设计说明书》的尺寸、默认状态与内容规则逐项核对（初始尺寸与排版、默认布局与条件式显示规则）。来源：`wp-00` 行 26；IXD §3.1、§3.2、§2.3、§20.3。

**DR-03 固定条件下的真实运行截图与检查结果。** 必须在固定窗口、字体与缩放条件下提供真实运行截图及检查结果；固定条件采用 IXD §18.4 回归样例（固定浅／深主题、1280×800 与 1024×640 窗口、200% 文字缩放），检查文本截断、焦点遮挡、层级、关闭入口及正文横向溢出，**而非只检查截图文件是否生成**。来源：`wp-00` 行 27；IXD §18.4。

**DR-04 测试执行与三类等价性禁令。** 必须按需求书与交互书执行对应测试；**编译通过不得替代交互验收，截图存在不得替代视觉核对，浏览器测试不得替代 Linux 桌面验证**。来源：`wp-00` 行 29–30；SRS §8.1（记录输入样例、环境、操作、实际结果及必要截图，不只写通过结论）；计划书 §4.4（桌面 WebDriver 用于实际应用，不以浏览器模拟替代文件入口、输入法与 WebKitGTK 验证）、§5.6（界面样例或固定演示数据不能代替真实文件与实际桌面运行）。

**DR-05 未可执行检查必须标记“未验证”。** 无法执行的检查必须明确标记为“未验证”，不得写成通过；测试不能执行时登记环境阻塞，不视为通过。来源：`wp-00` 行 31；SRS §8.4；计划书 §5.7（保留失败结果）；`config` 行 65。

**DR-06 最终交付物清单。** 最终必须交付：可构建源码、经过验证的 Linux 安装包（.deb）、实际测试结果、已知限制、使用说明，以及完整开源信息（GPL-3.0-only 未改写许可证全文、第三方声明、与二进制匹配的对应源码入口；版本与元数据一致）。来源：`wp-00` 行 33–34；`config` 行 17、行 55；SRS §8.4（真实安装包与源码版本、资源清单和许可证一致）、§4.10 R30。

**DR-07 仅 v0.1.0 范围，界面无未来占位。** 只实现 v0.1.0 范围；LaTeX/PDF、批注与源码结构等后续能力不得提前加入；首版界面不得放置未实现按钮或“建设中”占位。来源：`wp-00` 行 22–23；SRS §2.4、§9.1 末段；IXD §2.1（UI08 首版不放占位入口）、§2.2、§13.2；`config` 行 55。

**DR-08 输入只读与编号对应保留。** `input/` 必须保持原始输入不变（本基线未修改）；R／IX／AT 编号对应关系必须保留，不得重编号或改号。来源：`wp-00` 行 12、行 16；SRS §1.3（需求编号是产品追踪标识）；`config` 行 65；Intake §9 A12。
